## Цикл задачи

```
Alex ставит задачу в sprint-NN.md (с владельцем)
        │
        ▼
Агент создаёт ветку claude/... или codex/...  ──►  работает только в своей зоне
        │
        ▼
pnpm check локально  ──►  PR в main по шаблону  ──►  CI
        │
        ▼

        │
        ▼
Агент отмечает задачу в спринте выполненной
```

## Как фронт и бэк не мешают друг другу

1. **Контракт раньше реализации.** Новая функция начинается с PR Claude в `packages/shared`: схемы данных и сообщений + описание в [docs/api/README.md](../api/README.md). После мержа фронт и бэк работают параллельно.
2. **Фронт не ждёт данных.** Фикстуры в `packages/shared/src/fixtures` доступны сразу. Режим `SIMULATE=1` в API отдаёт живые фейковые данные по тому же протоколу.
3. **Запросы между зонами** пишутся в раздел «Запросы» текущего спринта: кто просит, что нужно, зачем. Владелец зоны берёт их в работу.
4. **Общие файлы.** `pnpm-lock.yaml` при конфликте не правится руками: перебазируйся на `main` и запусти `pnpm install`. Корневые конфиги меняет только Claude.

## Pull request

- Маленький: одна задача спринта, по возможности до ~400 строк изменений.
- Заголовок в формате Conventional Commits: `feat(web): панель слоёв со счётчиками`.
- Описание по шаблону `.github/pull_request_template.md`: что сделано, как проверить, затронут ли контракт, скриншот для UI.
- CI зелёный: `format:check`, `lint`, `typecheck`, `test`, `build`.

## Definition of done

- Работает в браузере (UI) или покрыто тестом (API, логика).
- `pnpm check` проходит.
- Тексты UI через i18n, цвета через токены.
- Документация обновлена, если менялись контракт, архитектура или процесс.
- Задача отмечена в спринте.

## Настройки GitHub (делает Alex один раз)

- Settings → Branches → Add rule для `main`: Require a pull request, Require status checks (`check`), запрет force push.
- Settings → General → Pull Requests: включить только Squash merging, автоудаление веток после мержа.
- Подключить Codex к репозиторию (Codex → Settings → GitHub), чтобы он мог открывать PR.
