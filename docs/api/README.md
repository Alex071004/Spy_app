# Контракт API

Источник правды: Zod-схемы в `packages/shared/src` (`model.ts`, `protocol.ts`, `api.ts`). Этот документ объясняет их словами. Если документ и код расходятся, прав код, а документ чинит Claude.

- База REST: `VITE_API_URL` (локально `http://localhost:4000`)
- WebSocket: `VITE_WS_URL` (локально `ws://localhost:4000/ws`)
- Текущая версия протокола: **1** (`PROTOCOL_VERSION`)

## Модель

**`TrackedObject`** описывает любой объект на глобусе:

| Поле        | Тип                  | Смысл                                                                                          |
| ----------- | -------------------- | ---------------------------------------------------------------------------------------------- |
| `id`        | string               | `"<layer>:<sourceId>"`, например `aircraft:4ca7b5`. Стабилен между обновлениями                |
| `layer`     | `LayerId`            | `aircraft` · `vessels` · `satellites` · `events` · `webcams`                                   |
| `position`  | `{ lon, lat, alt? }` | Градусы WGS84, высота в метрах над уровнем моря                                                |
| `heading?`  | number               | Курс 0…360°, 0 = север, по часовой                                                             |
| `speed?`    | number               | м/с относительно земли                                                                         |
| `updatedAt` | number               | Время данных от источника, unix ms. По нему клиент интерполирует движение                      |
| `source`    | string               | id коннектора, например `adsb-lol`, `simulator`, `fixture`                                     |
| `props`     | object               | Поля слоя. Пока свободные; типизированные схемы слоёв появятся в `packages/shared/src/layers/` |

`props` слоёв:

- `aircraft`: схема `AircraftPropsSchema` в `packages/shared/src/layers/aircraft.ts`. Всегда есть `onGround`; по возможности `callsign`, `type` (ICAO-код типа), `registration`, `squawk`, `category`, `verticalRate` (м/с), `emergency`, `military`; в симуляторе ещё `origin`, `destination` (IATA). Особые сквоки: `EMERGENCY_SQUAWKS`. Борта на земле приходят без `position.alt`
- `vessels`: `name`, `mmsi`, `shipType`, `flag`, `destination`

**`BBox`** = `[west, south, east, north]` в градусах. Если `west > east`, рамка пересекает антимеридиан (180°).

## WebSocket `/ws`

```
клиент                                   сервер
  │──────────── (connect) ────────────────►│
  │◄──── hello {protocol, time} ───────────│  сразу после подключения
  │──── sub {layers, bbox, z} ────────────►│  подписка (повторный sub заменяет)
  │◄──── snap {layer, items} ──────────────│  по одному на слой
  │◄──── delta {layer, up, rm} ────────────│  примерно раз в секунду
  │──── view {bbox, z} ───────────────────►│  камера сдвинулась
  │◄──── snap / delta ─────────────────────│
  │◄──── error {code, message} ────────────│  на некорректное сообщение
```

| Сообщение | Направление | Поля                                           |
| --------- | ----------- | ---------------------------------------------- |
| `hello`   | ←           | `server`, `protocol`, `time`                   |
| `sub`     | →           | `layers: LayerId[]`, `bbox`, `z` (0…22)        |
| `view`    | →           | `bbox`, `z`                                    |
| `snap`    | ←           | `layer`, `items: TrackedObject[]`              |
| `delta`   | ←           | `layer`, `up: TrackedObject[]`, `rm: string[]` |
| `error`   | ←           | `code` (`bad_json`, `bad_message`), `message`  |

Правила для клиента:

- Проверять `hello.protocol`. Не совпадает с `PROTOCOL_VERSION` → показать «Обновите страницу».
- Валидировать входящие сообщения `ServerMessageSchema.safeParse`.
- `z`: условный зум камеры (0 = вся Земля). На мелком зуме сервер прореживает объекты.
- При разрыве переподключаться с экспоненциальной задержкой и заново слать `sub`.
- **Двигать объекты самому.** Сервер пересылает объект не каждую секунду, а когда он резко изменился (поворот > 3°, скорость > 10%) или прошёл keyframe-интервал: самолёты 5 с, суда 30 с. Между обновлениями клиент ведёт объект по `heading` и `speed` от `updatedAt`: `deadReckon(obj, Date.now())` из `@spyapp/shared`.
- **Прореживание стабильно.** На мелком зуме сервер отдаёт не больше ~2 500 объектов слоя (z < 4), 4 000 (z < 6), 8 000 (дальше). Выбор детерминированный по id: одни и те же объекты не мигают от тика к тику.
- **`up` содержит объект целиком**, включая `props`. Это заменяет прежнюю версию объекта.

**Статус:** всё работает. Источники: симулятор (`SIMULATE=1`) или реальные самолёты из adsb.lol (`SIMULATE=0`), см. ниже.

## Реальные данные

`SIMULATE=0`: самолёты из adsb.lol. Ограничение бесплатного API: данные по всей планете обновляются раз в 1–2 минуты, области, которые клиенты смотрят с зумом ≥ 4, получают приоритет. Борта из списков приватности LADD/PIA не отдаются. Атрибуция для UI: «Aircraft data: adsb.lol (ODbL)». Глобальный фон в реальном времени появится с OpenSky (B2b).

## Режим симуляции

`SIMULATE=1` в `.env` (по умолчанию в `.env.example`) запускает фейковый мир без внешних API:

- **~10 000 самолётов** летят по большим кругам между 57 крупными аэропортами, набирают высоту и снижаются, после посадки уходят новым рейсом. У одного борта сквок `7700` для отладки сводки.
- **~5 000 судов**: 80% идут по 11 основным морским путям (Суэц, Малакка, Ормуз, Панама, Транспасифик...) туда и обратно, 20% рыбачат в известных районах.
- Количество: `SIM_AIRCRAFT`, `SIM_VESSELS`. Мир детерминированный: после рестарта те же борта и суда.

Замер на полном симуляторе, JSON:

| Вид                               | snap    | Дельты    |
| --------------------------------- | ------- | --------- |
| Весь мир, z = 2 (≈5 000 объектов) | 1,4 МБ  | ~195 КБ/с |
| Европа, z = 5 (≈2 300 объектов)   | 0,66 МБ | ~98 КБ/с  |

Сжатие трафика (props только при изменении, MessagePack) запланировано в B5.

## REST

| Метод | Путь                         | Ответ                                                  | Статус |
| ----- | ---------------------------- | ------------------------------------------------------ | ------ |
| GET   | `/health`                    | `HealthResponse`: `{ status: "ok", uptime, protocol }` | ✅     |
| GET   | `/api/search?q=&limit=`      | `SearchResponse`: объекты и места                      | ✅     |
| GET   | `/api/objects/:id`           | `ObjectDetailsResponse`: объект, название типа, фото   | ✅     |
| GET   | `/api/satellites/tle?group=` | `SatellitesResponse`: набор TLE группы                 | ✅     |

Ошибки REST приходят как `ApiError`: `{ error: "not_found" | "bad_request" | "unavailable", message }` с кодом 404, 400 или 503.

### `GET /api/objects/:id`

Для карточки-досье по клику. `id` как в потоке, например `aircraft:4ca6fb`.

- `object`: последнее состояние из мира (то же, что приходит в `/ws`).
- `typeName`: «Boeing 737 MAX 8» для `B38M`. Есть только для распространённых типов, иначе поле отсутствует.
- `photo`: фото с Planespotters или `null` (фото нет, источник недоступен, объект из симулятора).
- 404, если объекта сейчас нет в мире (пропал из зоны приёма, истёк TTL).

**Правила показа фото (условия Planespotters):** картинку грузить прямо по `thumbnailUrl`/`largeUrl`, не копировать к себе. Рядом всегда подпись «© {photographer} / Planespotters.net» со ссылкой на `pageUrl`. Ответ занимает до ~4 с при первом запросе борта, дальше кэш на час, поэтому досье показывать сразу по данным потока, а фото догружать.

### `GET /api/search`

Для строки поиска и команд `track`/`goto` (F4). `q`: от 2 символов, `limit`: 1…50, по умолчанию 20.

- Объекты (`kind: "object"`): самолёты по позывному, регистрации, hex и типу; суда по названию и MMSI. Выбор результата: камера к `position` + выбор объекта по `id`.
- Места (`kind: "place"`): пока только 57 крупных аэропортов, по коду и городу на русском или английском. Выбор: только камера. Поиск любых городов и адресов — задача B6.
- Порядок: точное совпадение, потом с начала строки, потом внутри (от 3 символов). Совпадение только по типу самолёта ниже позывных и регистраций.

REST-ответы больше 1 КБ сжимаются (gzip/brotli по `Accept-Encoding`), браузер распаковывает их сам.

### `GET /api/satellites/tle`

Спутники не идут через `/ws`: клиент получает набор TLE и сам считает позиции и орбиты через satellite.js (`twoline2satrec` + `propagate`). Схема `SatellitesResponseSchema` в `@spyapp/shared`.

- `group`: `stations` (по умолчанию: МКС, Тяньгун и др.), `visual` (видимые глазом), `gps`, `glonass`, `galileo`, `weather`, `starlink` (~10 600), `active` (все действующие, большой набор).
- Ответ: `{ group, fetchedAt, source, satellites: [{ noradId, name, line1, line2 }] }`. `ISS_NORAD_ID` = 25544 для отдельной подсветки МКС.
- Заголовок `Cache-Control: public, max-age=3600`: в течение часа браузер берёт набор из своего кэша.
- Сервер берёт данные с CelesTrak раз в 6 часов и хранит их на диске. Если CelesTrak недоступен, отдаётся последний набор (`fetchedAt` покажет его возраст). 503, если набора нет совсем.
- `SIMULATE=1`: встроенные реальные TLE на 2026-11-09 (`source: "fixture"`): 15 станций и 8 GPS, без сети. Со временем точность позиций падает.
