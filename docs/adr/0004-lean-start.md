# ADR-0004 · Lean-старт: один процесс, состояние в памяти

- **Статус:** принято (уточняет ADR-0003, заменяет первоначальный план с Redis и TimescaleDB с первого дня)
- **Дата:** 2026-11-02

## Контекст

Изначально планировались отдельный воркер ingest, Redis и Postgres + TimescaleDB с фазы 0. Для одного автора, который работает с Claude в быстром темпе, это лишняя инфраструктура: Docker, миграции, сетевые границы, и всё это до первого самолёта на экране.

## Решение

- В фазах 0–3 **один Node-процесс** `apps/api`: коннекторы, состояние мира, стриминг, детекторы, прокси.
- Live-состояние и короткие хвосты треков (~30 мин) хранятся **в памяти**.
- `services/ingest` упразднён, коннекторы живут в `apps/api/src/layers/<id>/connectors`.
- PostgreSQL появляется в фазе 4 (аккаунты), Redis при горизонтальном масштабировании, TimescaleDB для replay.

## Альтернативы

- Полная инфраструктура сразу: «правильно», но замедляет первые фазы в разы и требует Docker с первого дня.
- Без сервера, только клиент: ключи API утекли бы в браузер, плюс CORS и лимиты источников на каждого пользователя.

## Последствия

- Рестарт сервера стирает live-состояние, через несколько секунд оно восстанавливается из источников. Для live-данных это приемлемо.
- Длинной истории до этапа D нет, хвосты треков короткие.
- Коннекторы и детекторы не знают, где хранится состояние (работают через интерфейс `WorldState`), поэтому переезд на Redis не требует их переписывать.
