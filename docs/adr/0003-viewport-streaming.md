# ADR-0003 · Стриминг live-данных по viewport через WebSocket

- **Статус:** принято
- **Дата:** 2026-11-02

## Контекст

В мире одновременно летят ~10–15 тыс. самолётов, в AIS видны десятки тысяч судов. Слать всё всем клиентам каждую секунду дорого по трафику и тяжело для браузера.

## Решение

- Один WebSocket на клиента. Клиент сообщает **видимую область (bbox), зум и включённые слои**.
- Сервер индексирует объекты по тайлам и шлёт **snapshot** при подписке, затем **delta** (upsert/remove) каждые 1–5 с.
- На глобальном зуме выполняется прореживание или кластеризация на сервере.
- Формат: JSON до фазы 3, затем MessagePack. Схемы сообщений описаны в `packages/shared/src/protocol`.
- Клиент **интерполирует** позиции между обновлениями по скорости и курсу, чтобы движение было плавным.

## Альтернативы

- **REST-поллинг:** проще, но больше задержка, трафик и нагрузка.
- **Server-Sent Events:** однонаправленные, а нам нужно сообщать серверу о смене viewport.
- **Отдавать «весь мир» и фильтровать на клиенте:** 2–5 МБ/с на клиента, не масштабируется.

## Последствия

- Нужен механизм тайлового индекса на сервере (geohash / slippy tiles) и учёт подписок.
- Горизонтальное масштабирование: несколько инстансов API читают один Redis pub/sub.
